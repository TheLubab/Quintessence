In theory, I could make an AI generate HTML and CSS or similar languages that gets translated and there are already many attempts at that. But that have many issues that make lean in other directions.

Most chat interfaces already render generated HTML somehow. They even integrate it in the chat itself, i ask for a guide on something and they generate an interactive UI that actually demonstrate that well.

But I want to go completely other direction.

Instead of the interface being a support of the chat, what if the chat didn't even exist, or was the support of the interface.

User interaction would instead be transfered into a UI completely, no chat, at least no big chat interface.

I imagine the user opens the platform, and is met with options or intentions, of everything a user could want from his device? browse? shop? images? read? ask? message?

the user clicks and interface generates with sub tasks. that user continue clicking. until he reaches his gaol for example reading wikipedia article.

BUT very important thing is that I shouldn't build the interface, it should be live generated by an LLM live and displayed live. Therefore the name "alive ui".

That interface would be unique the user that uses it, and what state his platform accumalated. A sort of new way of thinking of an operating system.

It's completely empty. (potentially would need seeds to start tho)

The platform would held one unified state that include the ui + data in one thing. and that should be generated by the LLM.

That's why the hierchy of the HTML DOM might not work for it.

I want the LLM to be continously running, and consuming the state or at least stripped version of it, to know what is there, and generate the new objects that are showing to the user.

In complex scenarios there might be many objects, and html dom would be terrible for that.

Because we want everything to be instant, therefore the UI should be streaming the same way text is streaming. That would mean designing a new Layout/Rendering engine instead of relying on html. But for the prototype I can make a tronslation layer instead, from a streaming layout language to HTML by constraining many of the html features.

Second issue is good design. LLM don't know what looks good, it's terrible at generating good designs, because design relies on vision and changing and just some stuff that are not part of LLM. IDK much of the science.

Anyway, but LLM still can generate words that could be translated into betaufil design. I believe the secret sauce would be to give the LLM a new grammar for design, and our engine would convert that grammar into great design. Not sure yet about what.

What i am sure about, making the LLM generate raw CSS or shapes would end up horribly in design. What would work is to let the AI just says how things should feel.

A design grammar would contain things like hierchy, composition, typography, rythm, visual and audiotry feedback, and possible an animation/effects system for the fancy stuff.

that still need thinking.

But we sholud assume that AI will be terrible at designing, but great at understanding the intent. The goal is to let the LLM transform the intents into UI, not necessarily designs.

We need to introduce a new language and model in general that would be translated into a UI.

That language should have self contained objects.

think something like this

```diff
+screen main
+layout=floating density=confortable mode=editorial

+group main.actions
+position=0,0,0 origin=center layout=relative w=full aspect=square

+obj main.actions.btn_web
+position=2,0,0 origin=group-center attention-level=1
+icon=earth label=Browse

+obj main.actions.btn_gallery
+position=-2,0,0 origin=group-center attention-level=1
+icon=gallery label=Gallery

+txt main.title
+position=0,0,0 origin=top-center attention-level=2 size=1
+content=My Demo App
```

then when the user interacts with the ui, the llm receives something like this, in addition to the current state:

```diff
@click main.actions.btn_web
```

and llm responds with the following where `-` removes the node and `+` creates it

```diff
-group main.actions
+group main.input
+position=0,-1,0 origin=center layout=relative w=full aspect=square

+input main.input.txt
+position=0,0,0 origin=group-center attention-level=1
+placeholder=Input what you'd like to search

+obj main.input.submit
+position=0,1,0 origin=group-center attention-level=2
+label=submit
```

imagine the language is a tiny protocol that the model emits one complete operation at a time. with other operations like ~ to update nodes.

that's just a first rough idea

the lanugage exist to support streaming the user interface so that the user doesn't wait for the full output to render it, and each line should be atomic render that happens in the ui. and doesn't depend on the rest of the code, something like SQL.

Not sure about the technicilities of the implementation, potentially use something like Yoga layout and skia library from meta for rendering. Fine tune if needed/possible the model on this. ANd benchmark the speed to first render.

**DEMO** that would demonstrate the value

1. open the platform. no chat. no typical ui. few seeding intentions: Explore, Discover, Make, Organize. (or let user drag and drop something like a photo/csv/pdf etc)

2. User clicks a button, and watches the interface materialize immediately. Content appears streamingly an articel, an illustration, actions.

3. The interface doesn't even lose state. It compounds until user deletes it.
